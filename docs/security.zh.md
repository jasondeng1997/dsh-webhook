# 安全模型

[English](security.en.md) | 中文

dsh-webhook 把入站 HTTP 请求变成 Agent 会话输入，因此它本质上是一个「多了一层校验的远程执行面」。本页说明它防什么、怎么防，以及**不**做什么。

## 威胁模型

| 对手 | 假设能力 | 对应防御 |
|---|---|---|
| 任何能访问端口的人 | 任意请求体、任意请求头、任意量级 | 默认只监听回环、强制验签、请求体上限、读写超时、有界排队 |
| 合法发送方的重放或伪造 | 知道端点 URL，可能曾持有过有效密钥 | 每次请求重新解析密钥、常量时间比较、不给降级路径 |
| 恶意载荷作者 | 控制 JSON 里的每一个字节 | 模板不执行任何东西、只做路径取值、提示词截断 |
| 恶意回调接收方 | 控制回调 POST 的响应 | 只截取有限响应片段、`4xx` 不重试、请求体不含密钥 |
| 好奇的日志阅读者 | 能读启动日志、投递记录、`GET /healthz` | 载荷与请求头永不落日志；诊断信息只有 ID、阶段与耗时 |

## 鉴权

每条路由都用共享密钥鉴权，且**在解析请求体之前**完成校验：

| `source` | 方案 | 说明 |
|---|---|---|
| `github` | `x-hub-signature-256`（HMAC-SHA256 十六进制） | 旧版 `x-hub-signature`（SHA-1）**只在**强签名缺失时才参考，因此携带强签名的投递无法被降级 |
| `gitlab` | `x-gitlab-token`（密钥原样） | 常量时间比较；空格属于密钥的一部分，不做 trim |
| `gitee` | `x-gitee-token`（WebHook 密码） | 比较规则同上 |
| `generic` | `x-webhook-signature`（HMAC-SHA256 十六进制，`sha256=` 前缀可选） | 同时接受 GitHub 的头名，一个发送方可以服务两类端点 |

**解析不到密钥的端点一律返回 `401`**，不会退化成「没配鉴权所以放行」。要放弃鉴权必须显式写 `allowUnsigned: true`，而插件会在启动日志、`GET /healthz` 的问题计数以及设置卡片里持续报告这个状态。

密钥存放在凭据库中，按名字引用：

```yaml
routes:
  - id: ci
    secretRef: GITHUB_WEBHOOK_SECRET
```

`secretRef` **每次请求**都会经 Harness 凭据 seam 重新解析，因此轮换密钥立即生效，不需要重启或重连。内联的 `secret` 字段只用于本地试验，并会在每次启动时被报告为配置问题 —— 它会落在 profile 的配置树里，而那个文件经常被人粘到 issue 里。

## 载荷处理

- **体积**：超过 `maxBodyBytes` 的请求体返回 `413`。超限的请求体会被**读完再拒**，而不是直接断连 —— 让发送方知道被拒的原因，比让它看到一个连接重置更有用；超出上限的部分不会被保留。
- **形态**：JSON、表单编码、未知格式都能处理。声明自己是 JSON 但解析失败的请求体会降级为纯文本，而不是让这次投递失败 —— 一份能读的提示词比丢掉一个事件更有价值。
- **模板**：替换只做 `{{ 点路径 }}` 取值，没有表达式、没有辅助函数、没有 partial、不会二次替换。载荷里长得像占位符的值会被原样输出。这是整个插件最重要的一条性质：**一个可执行的模板等于把进程内的执行入口交给写载荷的人**。
- **截断**：超过 `maxPromptChars` 的渲染结果会被裁剪并标注，避免大载荷静默吃掉模型的上下文预算。

## 出站请求

回调投递与 `webhook_send` 工具共用同一套发送器：

- 只在**重试可能成功**时重试：传输失败、超时、`408`、`429`、`5xx`；
- `4xx` 从不重试 —— 被拒绝的请求重复发送就是小型洪水；
- 尊重 `Retry-After`（受调用方上限约束），其余情况指数退避；
- 回调请求头的值经过同一个沙箱渲染器；头名不合法、值里含 CRLF、或者是 `host` / `content-length` / `transfer-encoding` 的，一律丢弃而不是发送；
- 出站工具**默认关闭**，开启后还可以用 `sendToolAllowHosts` 收窄（`.example.com` 覆盖该域名及其子域）。

## 诊断而不泄露

- `GET /healthz` 只报告存活状态、版本、活跃路由条数和配置问题条数。它不列路由、不给会话 ID、不给计数器 —— 未鉴权的探测拿不到任何有价值的信息。
- `GET /deliveries` 需要 `managementToken`。没有配置 token 时该接口直接返回 `404`，因为「没设密码」绝不等于「空密码可用」。记录里只有投递 ID、路由 ID、上游类型、事件名、接收时间、阶段、耗时、会话 ID 和插件自己写的说明文本。**没有载荷、没有请求头、没有密钥、没有令牌。**
- 启动日志按字段名报告配置问题，绝不打印密钥**值**，只打印引用名。

## 过载

每条路由同时处理 `maxConcurrency` 条投递，最多再排队 `queueLimit` 条，超出后接收器返回带原因的 `503`。这是刻意的选择：支持重试的上游是比「进程内无限积压的 Agent 回合队列」更好的等待场所，而且**有界的拒绝**在投递记录里看得见，不断增长的积压看不见。

请求读取受 `requestTimeoutMs` 约束，HTTP 服务器同时设置了匹配的 header / request / keep-alive 超时，因此慢速或超大客户端无法长期占住一个槽位。

## 本插件不做的事

- **不做 TLS**。它只说明文 HTTP。请在它前面终止 TLS，或者把它留在回环里走隧道。
- **不做限流**。过载时的 `503` 是背压，不是限流器。公网端点前面请放代理。
- **不做来源白名单**。未配置的路径返回 `404`，但已配置的路径会接受任何持有密钥的人的签名请求。密钥泄露了就轮换 —— 这就是全部的重置手段。
- **不检查载荷内容**。桥只判断一次投递**是否真实**、**是否在范围内**，不判断它**是否合理**。载荷内的提示词注入是模型与你所写的 `instructions` 需要共同面对的问题，这也正是路由上存在 `instructions` 字段的原因。
